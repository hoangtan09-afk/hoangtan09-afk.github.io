# Getting familiar with concepts

## What is Container.vc?

**container.vc** is a **"locked virtual drive" using VeraCrypt**. Imagine it as a safe inside a computer: on the outside, it is just an unreadable data file, but inside it can contain many folders and documents. Only with the correct password or keyfile can we mount it to open and use it like a normal drive.

Along with it, we can see a "wordlist" file. This suggests a **Dictionary Attack**. From this information, we can predict that we could use **Hashcat** to try the passwords in the **wordlist** to find the correct password, then use it to **mount the container** and view the data inside.

<br>

## What is VeraCrypt?

**VeraCrypt** is a data encryption tool that allows creating virtual drives protected by a password or keyfile. When not mounted, the data inside only exists as an encrypted file and cannot be read directly. Only when the correct credentials are provided will the container be opened and function like a normal drive.

# Practical part

## Question 1: What is the hash type (-m flag) used by hashcat to crack the password?

We will use the following command with **Hashcat**:

```cmd
hashcat -m 13751 container.vc wordlist
```
**Command explanation:**
- **m 13751:** select VeraCrypt SHA-256 + XTS 512-bit (legacy) mode.
- **container.vc:** the VeraCrypt container file for which the password is to be found.
- **wordlist:** the list of passwords that Hashcat will try one by one.

**Output:**

![](/assets/img/posts/2026-07-11-Veriarty/2026-07-11-22-44-26.png)

**Answer: 13751**


## Question 2: What is the password to unlock the container?

Based on the results after running as shown in the image above, we can see that the password to mount the container later has been successfully cracked as: **jamie**

We proceed to mount the container with the password **jamie**, running the following two commands:

```cmd
sudo mkdir -p /mnt/vc_jamie
sudo veracrypt --text container.vc /mnt/vc_jamie
```

At the first password prompt, we enter **jamie**. The subsequent parts like **PIM** or **keyfile** are skipped by **pressing enter**.

## Question 5: When is the meeting supposed to be taking place?

To answer this question, we need to focus on the Decode Me.jpg file.

![](/assets/img/posts/2026-07-11-Veriarty/2026-07-12-20-31-59.png)



![](/assets/img/posts/2026-07-11-Veriarty/2026-07-12-20-32-49.png)

This image uses colored circles to represent binary numbers (binary-coded clock). We set the convention:

- **Red = 1**
- **Gray = 0**

Read each column from top to bottom, in the order of **day – month – hour – minute.**

Result:

- Column 1: 0101   = 5

- Column 2: 1011   = 11

- Column 3: 10000  = 16

- Column 4: 000101 = 5

Therefore, the meeting time is:

**5th November, 16:05**

**Answer: 5th November, 16:05**
